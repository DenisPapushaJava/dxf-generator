# Имена DXF и совместимость с CAM

Имя DXF разбирается последующей CAM-программой. Порядок полей, кириллица, единицы, десятичный разделитель и суффикс повтора имеют значение.

## Источник и решение

Исследован старый `DenisPapushaJava/dxfGeneratorwinforms`, commit `cf9ce056985dde6f3075c1d2da31398914c3efc0`:

- [GenerateDxf, Form1.cs:171–200](https://github.com/DenisPapushaJava/dxfGeneratorwinforms/blob/cf9ce056985dde6f3075c1d2da31398914c3efc0/Form1.cs#L171-L200) — построение имени.
- [GetUniqueFileName, Form1.cs:70–84](https://github.com/DenisPapushaJava/dxfGeneratorwinforms/blob/cf9ce056985dde6f3075c1d2da31398914c3efc0/Form1.cs#L70-L84) — суффиксы повторов.
- [LoadFromExcel, Form1.cs:281–317](https://github.com/DenisPapushaJava/dxfGeneratorwinforms/blob/cf9ce056985dde6f3075c1d2da31398914c3efc0/Form1.cs#L281-L317) — исходные поля.

**2026-10-19 автор подтвердил: CAM нужен десятичный разделитель запятая.** В новом приложении он фиксирован независимо от языка Linux/Windows. Старый код использовал C#-интерполяцию без заданной культуры, поэтому его разделитель зависел от региональных настроек Windows. Формат чисел внутри DXF остаётся с точкой.

Сам парсер CAM и реальные производственные файлы пока не исследованы. Проверки нового кода основаны на прежнем исходнике и подтверждённом разделителе; приёмка в CAM ещё нужна.

## Прежняя таблица Excel

Первый лист, первая строка — заголовок, данные начиная со строки 2. Колонки читаются по позиции:

| Столбец | Значение | Участие в имени |
| --- | --- | --- |
| A | Имя файла, необязательно | Основа имени, если строка не пустая |
| B | `Прямоугольник`, `Круг`, `Шайба` | При пустом A — первая кириллическая буква: `П`, `К`, `Ш` |
| C | Длина / диаметр / наружный диаметр | Первое число после буквы, если A пуст |
| D | Ширина / не используется в геометрии круга / внутренний диаметр | Второе число после буквы, если A пуст |
| E | Толщина | `_<толщина>мм`, только если больше нуля |
| F | Количество | `_<количество>шт`, только если больше нуля |

Для круга D всё равно читался и попадал в автоматическое имя, даже если не использовался в геометрии. Пустой D становился нулём. В новой модели `Part::circle_filename_width` сохраняет это значение без изменения контуров.

## Порядок полей

Если A задан:

```text
<A>[_<толщина>мм][_<количество>шт].dxf
```

Если A пуст:

```text
<П|К|Ш>_<C>_<D>[_<толщина>мм][_<количество>шт].dxf
```

Квадратные скобки обозначают необязательную часть старого формата и в имя не входят. Разделитель полей — `_`. `мм` и `шт` — строчные кириллические буквы без пробела после числа, расширение — `.dxf`. Новое ядро требует количество от 1, поэтому поле количества всегда присутствует. Неуказанная толщина не добавляется.

| Данные | Имя |
| --- | --- |
| A=`Пластина`, толщина 6, количество 8 | `Пластина_6мм_8шт.dxf` |
| A=`Шайба опорная`, толщина 2,5, количество 8 | `Шайба опорная_2,5мм_8шт.dxf` |
| A пуст, прямоугольник C=200, D=100, толщина 6, количество 8 | `П_200_100_6мм_8шт.dxf` |
| A пуст, круг C=150, D пуст, толщина 8, количество 3 | `К_150_0_8мм_3шт.dxf` |
| A пуст, шайба C=100, D=50, толщина 5, количество 10 | `Ш_100_50_5мм_10шт.dxf` |
| A пуст, прямоугольник C=200,5, D=100,25, толщина 2,5, количество 8 | `П_200,5_100,25_2,5мм_8шт.dxf` |
| A=`Пластина`, толщина не указана, количество 8 | `Пластина_8шт.dxf` |

Название не транслитерируется, пробелы не заменяются подчёркиваниями, введённое расширение не удаляется, строка не обрезается. Например, A=`Деталь.dxf` даёт `Деталь.dxf_1шт.dxf`, как в старом коде. Для чисел используется общий формат с 15 значащими цифрами и запятой. В обычных размерах целые числа записываются без дробной части.

## Повторы и существующие файлы

В пределах одной серии прежняя программа выдавала:

```text
Пластина_6мм_8шт.dxf
Пластина_6мм_8шт(1).dxf
Пластина_6мм_8шт(2).dxf
```

Суффикс добавлялся перед расширением, без дополнительного `_` и начиная с 1. Новый экспорт сохраняет этот вид и дополнительно учитывает регистр по правилам Windows. Он не изменяет имя из-за существующего файла: занятый путь останавливает весь пакет до записи, после чего можно выбрать другую папку. Это относится и к совпадению с существующей папкой. `NewOnly` дополнительно защищает файл, появившийся после проверки.

Старый набор имён очищался перед каждым экспортом и не проверял содержимое папки. Эту уязвимость к перезаписи не воспроизводим.

## Намеренные проверки нового приложения

- Действительно пустое A означает автоматическое имя. Название только из пробелов — ошибка; старый код считал его заданным.
- Запрещённые Windows символы, зарезервированные имена устройств и имена длиннее 255 UTF-16 единиц отклоняются. Скрытой замены символов/усечения нет, чтобы не менять CAM-идентификатор. Длина проверяется также после добавления `(1)`.
- Количество должно быть положительным целым; старое усечение дробного Excel-количества и отсутствие поля при нуле не воспроизводим.
- Толщина необязательна; при импорте пустая ячейка или 0 должны означать отсутствие. Отрицательная толщина — ошибка.
- Неизвестный тип и неверные размеры должны давать ошибку строки вместо пустого DXF.

Регрессионные примеры находятся в `tests/export_tests.cpp`: все три формы, заданное/пустое A, дробные числа при разных локалях, повторы, занятые пути и недопустимые имена. `tests/core_tests.cpp` также проверяет, что дополнительная колонка D круга не изменяет геометрию. В текущем редакторе показывается базовое имя выбранной позиции; полный список итоговых имён с суффиксами повторов появится вместе с таблицей импорта Excel.
