# Лицензии и распространение

Автор ещё не выбрал лицензию нового приложения. В репозитории намеренно нет MIT/GPL/другой лицензии на собственный код: публичный GitHub сам по себе её не задаёт. Это решение не препятствует подготовке каркаса.

Qt Core/Gui/Widgets доступны на условиях open source или коммерческой лицензии Qt. Статическая линковка с LGPL Qt возможна при выполнении её требований; она не означает автоматическую необходимость купить Qt. При распространении статического EXE обычно нужно предоставить необходимые материалы и инструкции для перелинковки с изменённым Qt, сохранить уведомления и тексты лицензий, предоставить требуемые исходники библиотек и выполнить остальные применимые условия. Один запускаемый EXE и отдельный архив юридических/исходных материалов совместимы как формат поставки.

Перед внешним релизом выбрать лицензию своего кода и способ выполнения условий Qt, зафиксировать точные исходники/параметры Qt и его встроенных библиотек, подготовить notices, лицензионные тексты и материалы для перелинковки. Артефакт ручного workflow предназначен для тестов; workflow не публикует GitHub Release и не готовит полный комплект распространения.

Официальное описание обязательств: [Qt LGPL obligations](https://www.qt.io/development/open-source-lgpl-obligations). Лицензии встроенных в Qt сторонних компонентов также должны попасть в комплект распространения по их условиям.

Планируемый QXlsx и dev-only ezdxf используют MIT. QXlsx сейчас отсутствует в сборке; ezdxf и Python не попадают в приложение. GPL-библиотека `libdxfrw` не подключена.
