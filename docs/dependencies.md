# Зависимости и бюджет размера

| Компонент | Версия / политика | Для чего | Статус |
| --- | --- | --- | --- |
| C++ standard library | C++20 | Модель, геометрия, DXF | Используется |
| Qt Core / Gui / Widgets | минимум 6.4, Windows CI и статический SDK 6.10.3 | Нативный desktop | Используется |
| CMake / Ninja | CMake ≥ 3.25 | Сборка; отсутствуют в поставке | Используются при разработке |
| QXlsx | v1.5.1.1, commit `8a13e1c86e5d4fb5e3b2fb09c7b632514f1d54ca` | Импорт `.xlsx` без Excel | Подключён статически, MIT |
| ezdxf | 1.4.3 | Независимое чтение/аудит тестовых DXF | Только проверки, MIT |

Версия Qt на машине разработки может отличаться в пределах поддерживаемого API; Windows-релиз 0.2.0 использует зафиксированный SDK. В `third_party/qxlsx` включена только библиотека (около 900 КиБ исходников), без её примеров и инструментов. Нет package manager, `FetchContent` и сетевой загрузки в обычном CMake configure.

## Почему этого достаточно

Qt Core даёт Unicode и файловые API. Qt Gui — рисование предпросмотра через QPainter. Qt Widgets — окно, таблица и диалоги выбора файла/папки. Этого достаточно для интерфейса и экспорта. Файлы проектов, Undo/Redo и раскладка не входят в текущую задачу и не обосновывают дополнительные зависимости.

Собственный DXF writer ограничен двумя типами сущностей и не предназначен для чтения чужих файлов. Это осознанная небольшая область, проверяемая независимым `ezdxf` и в дальнейшем целевой CAD/CAM. [Autodesk: LWPOLYLINE](https://help.autodesk.com/cloudhelp/2017/ENU/AutoCAD-DXF/files/GUID-748FC305-F3F2-4F74-825A-61F04D757A50.htm). `libdxfrw` не добавлен: полноценное чтение не нужно, а GPL требует отдельного решения о лицензии проекта.

[QXlsx](https://github.com/QtExcel/QXlsx) под MIT подключён статически для импорта XLSX. Использует уже имеющиеся Qt Core/Gui и их private ZIP API. На Linux нужны matching private headers; на текущей машине пакет распакован в игнорируемую `build/deps/qt-private` без установки в систему. `DXFGEN_QT_PRIVATE_HEADERS` позволяет указать этот корень при configure. В поставку private headers и средства подготовки не входят. В Release для библиотеки включаются оптимизация размера и удаление неиспользуемых функций вместе с остальным приложением.

Небольшие локальные исправления чтения перечислены в [UPSTREAM.md](../third_party/qxlsx/UPSTREAM.md): корректная обработка чисел, пустого кэша формул, inline rich text и повреждённого XML. Формулы не вычисляются; используется сохранённый результат или выдаётся ошибка строки. Полный EXE 0.2.0 с XLSX, галереей, обновлением и лицензиями занимает 17,18 МиБ. Отдельная прибавка каждой функции не измерялась; общий прирост относительно прежних 16,26 МиБ — около 0,92 МиБ.

Старая программа читала и `.xls`, и `.xlsx`. QXlsx покрывает только `.xlsx`: поддержка старого двоичного `.xls` потребует отдельного решения и оценки зависимости. До этого явно показывать ограничение формата, не выдавая его за полную совместимость со старым импортом.

## Один EXE и размер

Приложение линкуется только с нужными модулями. Динамический SDK содержит и другие модули, но это не причина включать их в приложение. В ручном статическом Qt отключены Network, SQL, DBus, PrintSupport, TestLib, OpenGL/Vulkan; используются доступные встроенные сторонние зависимости. Встраивается только необходимый Windows platform plugin; графический значок рисуется кодом, шрифты и дополнительные image plugins не поставляются.

Release: оптимизация размера, удаление неиспользуемых секций и IPO для кода проекта. Qt собирается `-optimize-size`; статический runtime убирает зависимость от распространяемых отдельно библиотек компилятора. UPX и распаковщики не используются.

Первое измерение статического EXE на MSVC 2022 / Qt 6.10.3: **16,26 МиБ** без упаковщиков (ранний артефакт). Релиз 0.2.0 со всеми реализованными функциями: **17,18 МиБ**, рост около 0,92 МиБ. [Точный размер, SHA-256 и проверки](windows-single-exe.md#проверенный-релиз-020). В ручном CI установлен бюджет **20 МиБ**: запас для следующей функциональности с обязательным пересмотром при превышении. `verify_windows_exe.py` печатает размер и проверяет обычные и delay imports. Каждую новую библиотеку оценивать по изменению итогового артефакта, а не сумме import libraries.

Справка и сохранение шаблона используют существующие Qt Widgets/Core. Книга `examples/Детали.xlsx` с П / К / Ш встроена в Qt resource; дополнительных библиотек, сетевого доступа и Excel runtime не требуется.

## Ручные обновления

`dxfgen_update` использует существующий Qt Core (JSON, SHA-256, файлы, потоки) и системный WinHTTP на Windows 10/11. Qt Network, OpenSSL и сторонняя updater-библиотека не добавлены. На Linux для разработки проверка вызывает установленный curl; Windows-поставка его не содержит. Итоговый EXE 0.2.0 занимает 17,18 МиБ; реальный Windows-переход, отмена и откат прошли в релизном CI. Отдельная прибавка только updater не измерялась. [Контракт релиза и очистка](updates.md).

## CSV и TSV

Чтение текстовых списков использует существующий Qt Core: QFile, QString и QStringDecoder. Для Windows-1251 применяется небольшая таблица Unicode, без Qt Core5Compat, iconv и новых библиотек. Кодировки и разделитель подтверждаются существующими Qt Widgets. Добавлены небольшие примеры CSV/TSV; весь EXE 0.2.0 занимает 17,18 МиБ. Отдельная прибавка текстового импорта не измерялась.

Галерея всех деталей использует существующие Qt Widgets/Gui (QListView и QPainter), без новых библиотек. Миниатюры создаются только при отрисовке и хранятся в кэше до 12 МиБ; отдельные виджеты и изображения для всего списка заранее не создаются.
