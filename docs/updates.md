# Ручное обновление portable-версии

«?» → «Проверить обновления…». При запуске приложения, открытии Excel или справки сетевых запросов нет. Кнопка обращается к публичному API `DenisPapushaJava/dxf-generator`, показывает стабильную версию и описание изменений. При отсутствии Releases выводится обычное сообщение; проверка не считается успешной установкой.

На Windows x64 кнопка «Обновить и перезапустить» скачивает и проверяет EXE. Неэкспортированные правки списка защищены существующим подтверждением; отмена сохраняет список и не начинает загрузку. Ошибка сети, неподходящий релиз или неверный файл не заменяют работающую программу. Данные Excel/DXF не отправляются в сеть и не изменяются обновлением.

На Linux доступны ручная проверка и просмотр релизов. Установка Windows EXE отключена. Для сетевой проверки на машине разработки используется установленный `curl`, без чтения его пользовательского конфигурационного файла. В поставку Windows curl не входит: там используется системный WinHTTP, без Qt Network, OpenSSL или отдельной updater-библиотеки.

## Контракт GitHub Release

- Публичный репозиторий: `DenisPapushaJava/dxf-generator`.
- Только опубликованный стабильный релиз: `draft=false`, `prerelease=false`.
- Тег `vX.Y.Z` (также принимается `X.Y.Z`), без суффиксов предварительных версий. Сравнение числовое, обновление только на более новую версию.
- Ровно один asset `dxf-generator-windows-x64.exe`, `state=uploaded`, размер от 256 байт до 64 МиБ.
- Обязателен `digest` вида `sha256:…` из API GitHub. При отсутствии суммы автоматическая установка недоступна.
- HTTPS-ссылка asset должна вести именно на этот репозиторий и тег. Перенаправления разрешены только на `github.com`, `api.github.com`, `release-assets.githubusercontent.com`, `objects.githubusercontent.com`; переход на HTTP и произвольные серверы запрещён.
- После загрузки проверяются размер, SHA-256, сигнатуры PE32+ и архитектура x64. SHA-256 подтверждает целостность относительно доверенных метаданных GitHub, а не заменяет цифровую подпись издателя.
- Версия EXE из `CMakeLists.txt` должна совпадать с версией тега. Несовпадение не подтверждает успешный запуск; помощник восстанавливает предыдущую версию после завершения неподходящего процесса.

GitHub API: [Releases](https://docs.github.com/en/rest/releases/releases). Сетевой транспорт Windows: [WinHTTP](https://learn.microsoft.com/en-us/windows/win32/winhttp/about-winhttp). TLS-проверка сертификатов остаётся включённой; таймауты, предел размера и число перенаправлений ограничены. Авторизация GitHub и встроенные токены не нужны.

## Замена и очистка

Установка и обычная работа остаются portable. Папка программы должна быть доступна для записи. Административное повышение прав, службы, задания планировщика и регистрация установки не используются.

Подготовка создаёт одну уникальную папку `.dxfgen-update-XXXXXX` рядом с программой. В ней находятся новый EXE, временная копия текущего EXE в режиме помощника, служебные файлы и резервная копия. Поставка пользователю остаётся одним EXE; во время обновления требуется место для нескольких копий.

Помощник проверяет привязку к конкретному EXE, случайный токен и процесс родителя, сигнализирует о готовности и ждёт закрытия приложения. Старый файл копируется в резерв, новый заменяет его на том же томе через `MoveFileExW` без предварительного удаления целевого файла. Если новый процесс не запускается или завершается до подтверждения запуска, проверенная резервная копия возвращается на место.

Новая версия подтверждает запуск после создания главного окна и входа в цикл событий. После выхода помощника удаляются резервная копия, помощник, временные и служебные файлы вместе с папкой. При отмене до перезапуска подготовленные файлы также удаляются. При прерванном обновлении следующий обычный запуск выполняет только локальную очистку, без обращения к GitHub. Пока помощник работает, его файлы защищены блокировкой.

Очистка ограничена папками с нашим маркером владельца и известными именами файлов. Она не обходит вложенные каталоги, не следует символьным ссылкам/reparse points и отказывается удалять неожиданные файлы. Резерв не удаляется, пока работоспособная целевая версия не подтверждена. Если восстановление невозможно или файл изменён извне, резерв остаётся для восстановления; приложение не выдаёт этот случай за успешное обновление.

## Проверки и первый выпуск

Локальные тесты `update_safety` проверяют метаданные, целостность, подмену путей/файлов, блокировки, замену, восстановление, прерванную подготовку и очистку без изменения Excel/DXF. `update_workflow` проверяет окно, сообщения об ошибках, показ заметок обычным текстом и отмену запроса. Сеть в обычных тестах заменена управляемым ответом; отдельный ручной запрос: `./build/dev-linux/dxfgen_update_tests --live-check`.

В релизе 0.2.0 реальный Windows-переход проверен на Windows runner: старое тестовое приложение запускает настоящий помощник, который заменяет его финальным статическим GUI EXE 0.2.0. Проверены успешный запуск/подтверждение, отмена и восстановление предыдущего EXE при сбое запуска. Все сценарии выполняются в папке с кириллицей и пробелами; временные файлы удалены, контрольные Excel/DXF не изменены. [Успешная проверка 9/9 и PE-аудит](https://github.com/DenisPapushaJava/dxf-generator/actions/runs/39402143696). WinHTTP отдельно проверен реальным запросом к GitHub API. Поведение конкретного антивируса и ручная работа на чистых Windows 10/11 этим не подтверждаются.

Первый выпуск имеет версию 0.2.0. Более ранней публичной версии для пользовательского обновления пока нет; сценарий замены проверен тестовой предыдущей версией. После публикации контракт метаданных и скачивание финального asset дополнительно проверяются через тот же код проверки релиза.

Для последующих выпусков: повысить версию проекта, собрать и проверить статический EXE, выполнить Windows-тест перехода и очистки, затем опубликовать стабильный Release с asset указанного имени. Публикация, push и Windows CI выполняются по отдельному запросу или на этапе релиза; обычная локальная разработка их не запускает.
