# Архитектура

## Границы

- `include/dxfgen`, `src/core` → `dxfgen_core`: C++20 без Qt. Типизированные формы через `std::variant`, единая валидация, геометрия и узкий DXF writer.
- `src/io` → файловая граница на Qt Core. Планирует весь пакет, проверяет имена Windows и занятость путей, создаёт новые файлы без перезаписи.
- `src/desktop/parts_model.*` → модель списка; флаг включения в экспорт отделён от параметров детали.
- `src/desktop/preview_widget.*` → рисует `make_drawing()`. Не вычисляет собственную альтернативную геометрию.
- `src/desktop/main_window.*` → компоновка экрана, редактор и соединение действий с моделью. Будущие импорт/сохранение/раскладка сюда не добавляются монолитными обработчиками.
- `tests`, `scripts` → проверки, не зависимости приложения.

Поток: редактор → `Part` → `validate()` → `make_drawing()` → предпросмотр или `write_dxf()`. Экспорт повторяет валидацию, даже если кнопка уже отключена для ошибочных данных. Текст ошибки привязан к полю через `Field`; при добавлении локализации сообщения можно вынести из ядра без изменения правил.

## Инварианты

Все размеры — миллиметры. Размер/толщина конечны, больше нуля и не больше 1 000 000 мм. Количество — целое от 1 до 1 000 000. У шайбы `0 < inner < outer`. Толщина необязательна, не задаёт 3D-геометрию.

Прямоугольник имеет четыре вершины и флаг замыкания, круг — точную окружность, шайба — две концентрические окружности. Начало координат — нижний левый угол габарита, Z = 0. Количество не размножает контуры в файле. Имена и надписи не попадают в геометрию DXF. Числа сериализуются с точкой независимо от локали машины.

## Файлы

Имена очищаются от разделителей и запрещённых в Windows символов; имена устройств защищены префиксом. Конфликты учитываются без учёта регистра и получают `_2`, `_3` и т. д. Перед первым файлом проверяется и сериализуется весь пакет. Открытие с `NewOnly` защищает также от файла, появившегося после планирования.

Пакет не является транзакцией: при ошибке диска уже завершённые файлы сохраняются и перечисляются в результате. Текущий незавершённый файл удаляется при обнаруженной ошибке записи. При аварийном завершении процесса возможен неполный текущий файл; атомарный пакет с журналом не входит в каркас. Приложение не выдаёт такой пакет за успешный.

## Следующие этапы

1. **Файл комплекта**: версионируемый JSON через Qt Core, атомарное сохранение `QSaveFile`, явное состояние изменений, восстановление после сбоя. Сейчас данные только в памяти, при закрытии изменённого комплекта есть подтверждение.
2. **CSV**: явное сопоставление колонок и единиц, корректные кавычки/разделители, предварительный просмотр импорта, отчёт по строкам. Не угадывать молча типы и дробное количество.
3. **XLSX**: подключить выбранную версию QXlsx только вместе с реализацией. Значения формул без доступного численного результата считать ошибкой, а не нулём. `.xls` не включать автоматически.
4. **Профили экспорта**: проверенные варианты DXF под реальные CAD/CAM, проверка на целевых программах, отчёт и предпросмотр имён до экспорта. Если понадобится полноценное чтение/редактирование DXF — пересмотреть собственный writer и выбор библиотеки.
5. **Удобство**: дублирование деталей, Undo/Redo через уже имеющийся Qt Gui, фильтр ошибок, клавиатурные сценарии. Довести оформление до прототипа без тяжёлого UI-фреймворка.
6. **Расширения по реальной потребности**: дополнительные параметрические формы, материал, партии, раскладка. Не включать nesting/CAD-ядро заранее: это отдельные требования к геометрии, проверкам и лицензии.

Для текущих малых комплектов вычисления синхронные и быстрые. Фоновую работу добавлять для измеренного длительного импорта/экспорта с отменой и прогрессом; сервер, БД, контейнер зависимостей и система плагинов сейчас не нужны.
