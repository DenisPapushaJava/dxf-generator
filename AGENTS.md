# Development rules

- Keep this a small offline C++20/Qt Widgets utility for Windows 10/11 x64, developed on Linux.
- The primary workflow is Excel/CSV/TSV list → row validation and preview → DXF files in a chosen folder. Prioritize this complete path over manual editing features. Project/kit files, nesting, materials and Undo/Redo are outside the current scope.
- DXF filenames are an interface consumed by CAM. Follow `docs/cam-filenames.md`: comma decimals independent of OS locale, optional source name, legacy field order and `(1)` duplicate suffixes. Do not silently sanitize identifiers or invent separators/suffixes.
- Circles use only one dimension in automatic filenames: `К_<diameter>[_<thickness>мм]_<quantity>шт.dxf`. Do not add a second dimension or zero placeholder; ignore Excel column D for circles. This is the owner's explicit change from legacy naming.
- Manual creation has no name input: use automatic shape/dimension filenames. The optional custom name is only source metadata from Excel; keep it when editing imported parameters.
- `dxfgen_core` must have no Qt or other third-party dependencies. Geometry, validation and DXF serialization belong here, not in widgets.
- Preview and export must consume the same generated geometry. Dimensions are a preview overlay, never cutting geometry.
- All list formats share the six-column A–F schema and `parse_row()`. Accept Cyrillic П / К / Ш and full shape names, case-insensitive; preserve raw cells while displaying full names. CSV/TSV must respect quoted fields, comma decimals, physical source line numbers and structural errors. Detect UTF-8 and UTF-16 BOMs; require user confirmation for legacy Windows-1251 instead of silently guessing.
- XLSX import reads the first sheet, columns A–F, data from row 2. Preserve Excel row numbers and errors; never silently drop invalid rows. Formula results must be cached, not calculated or replaced with zero. `plan_file_names()` is shared by table previews and export, including duplicate suffixes.
- Table editing is authorized: imported name/type/dimensions/thickness/quantity and manual parameters can be edited locally. Source row numbers and derived filename/status are read-only; manual names stay automatic. Use the same `parse_row()` for import and edits, preserving untouched per-cell Excel errors and numeric precision. Never write edits back to the source workbook. Protect unexported edits on reload, including excluded rows. On exit always show one simple “Закрыть программу?” Yes/No confirmation (default No), with no additional unsaved-changes prompt; No keeps all edits.
- GitHub updates are explicitly authorized only on a user click. Keep the portable single-EXE distribution: Windows uses system WinHTTP, no Qt Network/updater framework. Accept only newer stable releases from our fixed repository with a verified x64 EXE and SHA-256. Protect pending table edits; keep backup until startup acknowledgement, clean only owned update files, and recover/clean interrupted attempts locally without any automatic network request. See `docs/updates.md`.
- Default configuration must not download dependencies. Add libraries only for implemented requirements; document purpose, version, license and binary-size impact.
- Do not overwrite existing user files silently. Validate all parts before starting a batch, and prevent paths from escaping the export directory.
- Keep builds and local toolchains in ignored directories. Never commit connector state, credentials or machine-specific paths.
- Work locally on Linux. Do not push, dispatch GitHub Actions, build/download Windows EXEs or refresh artifact records after routine changes. Do those only on an explicit user request or at an agreed release checkpoint. Group local commits by meaningful changes rather than every small adjustment.
- Use the smallest relevant local check: no build for documentation-only changes; a local build/visual check for UI changes; focused tests for geometry, validation, filename or export changes. Do not run every preset or repeat passing checks without a concrete reason. Windows single-EXE claims still require a real static build and PE audit when that verification is requested.
- Own project code is MIT, selected by the owner for the first release. Preserve separate Qt LGPLv3 and bundled third-party terms. Public static releases include the corresponding application/Qt sources, notices and rebuilding instructions; do not change Qt licensing assumptions without the owner's decision.
