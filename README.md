# DXF Generator

Небольшая офлайн-утилита для подготовки DXF плоских деталей. Новое приложение на **C++20 + Qt Widgets**, разработка на Linux, целевая платформа — **Windows 10/11 x64**. Это новая кодовая база, без переноса WinForms и его зависимостей.

## Основной сценарий

**Перетащить XLSX / CSV / TSV → проверить список → выбрать папку → получить DXF.** Источник данных — табличный список; отдельный файл проекта/комплекта не нужен. Один DXF на позицию, количество передаётся в имени для CAM, а не копиями контуров.

Текущий объём работы: импорт таблицы, понятные ошибки по строкам, предпросмотр выбранной детали и экспорт с совместимыми именами. Раскладка и расширение ручного редактора в этот этап не входят.

## Текущее состояние

Работает загрузка `.xlsx`, `.csv`, `.tsv` и табличного `.txt` кнопкой или перетаскиванием. Формы можно обозначать `П / К / Ш` или полными названиями. Таблица нумерует детали с 1 и показывает параметры, ошибки и итоговые имена DXF; справа — предпросмотр выбранной детали. Все строки загружаются отмеченными: ошибки блокируют экспорт, пока их не исправить в таблице программы/Excel или явно не исключить флажками/кнопкой «Выбрать готовые». Ячейки редактируются двойным щелчком/F2, форма выбирается из списка, Enter/Tab применяет ввод. Ошибки, предпросмотр и имена DXF обновляются после каждой правки; исходный файл не изменяется. Экспорт создаёт один DXF на выбранную позицию в указанной папке.

Кнопка «Все детали…» рядом с предпросмотром открывает прокручиваемую галерею всего списка. Карточки показывают размеры, толщину, количество, имя DXF и ошибки; включены также строки, не отмеченные для экспорта. Двойной щелчок, Enter или «К строке в списке» возвращает к выбранной строке. Флажок «В экспорт» на карточке и Пробел меняют общий выбор с таблицей. Счётчик и итоговые имена обновляются сразу; параметры деталей остаются прежними.

«Создать вручную…» всегда открывает новую деталь: размеры и необязательная толщина пустые, количество — 1. Форма не копирует выбранную строку. После добавления параметры редактируются прямо в таблице; отдельного диалога изменения нет. Поле названия не требуется. Имена строятся автоматически; у круга только диаметр: `К_150_8мм_3шт.dxf`. Название из столбца A Excel сохраняется. Дробные числа имени — с запятой; повторы получают `(1)`, `(2)`. Имена в таблице и экспорте рассчитываются одним планировщиком. Недопустимое имя или занятый путь останавливает пакет до записи. [Правила имён](docs/cam-filenames.md).

Кнопка «?» рядом с «Открыть Excel…» (F1) показывает структуру столбцов и сохраняет встроенный шаблон `.xlsx` с примерами. В справке также доступна ручная проверка GitHub Releases и обновление Windows portable-версии; [механизм и правила выпуска](docs/updates.md). Начать также можно с примеров [XLSX](examples/Детали.xlsx), [CSV](examples/Детали.csv) и [TSV](examples/Детали.tsv) с обозначениями `П / К / Ш` или [примера с ошибками](examples/Детали-с-ошибками.xlsx). Импортируется первый лист, столбцы A–F, данные со строки 2. Поддерживается `.xlsx`; старый `.xls` нужно сохранить как `.xlsx`. [Правила чтения Excel](docs/excel-import.md).

## Сборка на Linux

Текущий режим — локальная разработка на Linux. Проверки выбираются по изменению: для документации сборка не нужна, для интерфейса достаточно локальной сборки/просмотра, для геометрии и экспорта — соответствующих тестов. Push, GitHub Actions и обновление Windows EXE выполняются по отдельному запросу или на согласованном этапе релиза.

Нужны CMake ≥ 3.25, Ninja, компилятор C++20 и Qt ≥ 6.4 с Core/Gui/Widgets и соответствующими private headers для ZIP. На Ubuntu/Mint пакеты: `build-essential cmake ninja-build qt6-base-dev qt6-base-private-dev libgl1-mesa-dev`. QXlsx включён исходниками в репозиторий, обычный configure не обращается к сети.

```sh
cmake --preset dev-linux
cmake --build --preset dev-linux --parallel 4
ctest --preset dev-linux
./build/dev-linux/dxf-generator
```

На текущей машине private headers распакованы локально в `build/deps/qt-private`, путь уже записан в игнорируемом CMake cache. F5 в VS Code работает без дополнительных настроек. Для повторной подготовки без установки пакетов в систему:

```sh
mkdir -p build/deps
cd build/deps
apt-get download "qt6-base-private-dev=$(dpkg-query -W -f='${Version}' qt6-base-dev)"
dpkg-deb -x qt6-base-private-dev_*.deb qt-private
cd ../..
cmake --preset dev-linux -DDXFGEN_QT_PRIVATE_HEADERS="$PWD/build/deps/qt-private/usr/include/$(dpkg-architecture -qDEB_HOST_MULTIARCH)/qt6"
```

Запустить сразу с примером: `./build/dev-linux/dxf-generator --open examples/Детали.xlsx`. Сфокусированные проверки импорта и экспорта: `ctest --preset dev-linux -R 'excel_import|excel_workflow|export_safety'`.

Профиль `release-linux` включает оптимизацию размера и IPO. Все результаты находятся в игнорируемой `build/`; настройки машины можно добавить в игнорируемый `CMakeUserPresets.json`.

Проверить ядро вообще без Qt:

```sh
cmake --preset core-only
cmake --build --preset core-only
ctest --preset core-only
```

`sanitize-linux` проверяет ядро с ASan/UBSan. Для снимка настоящего окна без рабочего стола:

```sh
QT_QPA_PLATFORM=offscreen ./build/dev-linux/dxf-generator --screenshot build/window.png
```

## Запуск из VS Code на Linux

Открыть **папку проекта целиком**. Нужны расширения C/C++ (`ms-vscode.cpptools`), CMake Tools (`ms-vscode.cmake-tools`) и GDB. Рекомендации расширений сохранены в `.vscode/extensions.json`. В `.vscode` находятся общие настройки проекта, глобальные настройки редактора не требуются.

- **F5** — собрать Debug и запустить `DXF Generator (Linux Debug)` с отладчиком. Точки останова работают в C++-исходниках.
- **Ctrl+F5** — собрать и запустить без отладки.
- **Ctrl+Shift+B** — сконфигурировать и собрать профиль `dev-linux`.
- **Терминал → Выполнить задачу → DXF: run** — обычный запуск приложения.
- **Терминал → Выполнить задачу → DXF: test** — сборка и CTest.

Запуск по F5 использует явный путь к приложению и не зависит от выбранной в CMake Tools тестовой цели. Конфигурация выполняется задачей перед сборкой; при открытии папки мастер выбора компилятора не запускается. Быстрая кнопка C/C++ для сборки отдельного активного файла скрыта; используйте F5 или панель «Запуск и отладка». C/C++ берёт стандарт языка, Qt include paths и определения из `build/dev-linux/compile_commands.json`. Настройки запуска рассчитаны на Linux; Windows EXE собирается отдельно описанным ниже способом.

## Windows и один EXE

Для обычной разработки: MSVC 2022 x64, Ninja и Qt 6.10.3 MSVC 2022, терминал с окружением компилятора и Qt в `CMAKE_PREFIX_PATH`:

```powershell
cmake --preset dev-windows
cmake --build --preset dev-windows
ctest --preset dev-windows
```

Релизный профиль `release-windows-static` требует **отдельно собранный статический Qt** и `QT_STATIC_ROOT`. Он отвергает динамический Qt; одной настройки CMake недостаточно, чтобы превратить обычный Qt SDK в один EXE. Цель — один EXE без Qt/MSVC/MinGW DLL рядом, с использованием системных DLL Windows.

В Actions есть обычный CI Linux/Windows и отдельный ручной workflow **Windows single EXE (manual)**: сборка минимального QtBase, статический runtime, импорт Windows-плагина, тесты и проверка PE-зависимостей. Это процесс получения тестового артефакта, а не публикация готового релиза. Подробности: [сборка Windows](docs/windows-single-exe.md), [условия распространения](docs/licensing.md).

**Релиз 0.2.0, проверено 2026-10-20:** один EXE **18 012 160 байт (17.18 МиБ / 18.01 МБ)**, без упаковщика и внешних Qt/CRT DLL. Все 9 тестов статической Windows-сборки прошли, включая реальный переход на новый EXE, отмену, откат и очистку в пути с кириллицей и пробелами. PE-аудит обычных и отложенных импортов прошёл. [Сборка и проверки](https://github.com/DenisPapushaJava/dxf-generator/actions/runs/39402143696). Бюджет 20 МиБ соблюдён. Ручная проверка на чистых Windows 10/11 и конкретной CAD/CAM остаётся отдельным этапом.

[Скачать portable EXE и примеры](https://github.com/DenisPapushaJava/dxf-generator/releases/tag/v0.2.0). Исходники и материалы для пересборки Qt предоставлены отдельным архивом; для запуска они не требуются.

## Зависимости и устройство

| Задача | Решение сейчас |
| --- | --- |
| Геометрия, валидация, DXF | Стандартная библиотека C++20, без Qt |
| Окно, модель списка, рисование | Qt Core + Gui + Widgets |
| Файлы, Unicode, безопасные имена | Qt Core |
| Проверки ядра и файлов | CTest + небольшие тестовые исполняемые файлы |
| Независимый аудит DXF | ezdxf 1.4.3 **только в окружении проверок**, не в приложении |
| Excel `.xlsx` | QXlsx v1.5.1.1, статически из закреплённых исходников, MIT |

В обычной конфигурации нет `FetchContent` и загрузки пакетов. Приложение обращается к GitHub только по кнопке проверки/обновления; при запуске и работе с Excel/DXF сетевых запросов нет. Не используются QML, WebEngine, Qt Network/SQL, OpenCascade, .NET, Python runtime. [Обоснование зависимостей](docs/dependencies.md), [архитектура и дальнейшие этапы](docs/architecture.md).

## Проверки DXF

Необязательная проверка другим парсером в отдельном окружении разработки (нужен пакет `python3-venv`):

```sh
python3 -m venv build/dxf-audit
build/dxf-audit/bin/pip install ezdxf==1.4.3
build/core-only/dxfgen_fixture build/fixtures
build/dxf-audit/bin/python scripts/check_dxf.py build/fixtures
```

Она проверяет единицы, типы и число контуров, размеры, замыкание прямоугольника, концентричность шайбы и отсутствие исправлений при DXF-аудите.
